# Bytemeter

A macOS menu bar app in Swift that counts the bytes the Mac's network interfaces carry, with a dashboard and a CSV export. Its only claim is that its figures match what the interfaces carried, so every rule below protects that.

## Commands

- Test: `swift run -c release BytemeterSelfTest` (the gate: a Stop hook runs it at the end of every turn; builds first, then prints how many checks ran and exits non-zero if any failed; needs only the Command Line Tools)
- Build: `swift build -c release`
- Fonts check: `python3 Scripts/make_fonts.py --check` (the embedded fonts must match their files; CI runs it first)
- Install locally: `./install.sh` (`--dry-run` says exactly what would happen; `--help` lists the options)
- Version, icon, release, Homebrew and screenshots: MAINTENANCE.md is the authority. Read the section the task needs; nothing from it is copied here.

## Layout

The table in MAINTENANCE.md, "How it fits together", names every part. In short: `Sources/BytemeterCore` is the engine, `Sources/BytemeterDashboard` the page and the export, `Sources/Bytemeter` the macOS app, `Sources/BytemeterSelfTest` the checks (one file per subject, shared helpers in `Harness.swift`), `VERSION` the version, `Scripts/` the generators and templates, `Resources/` the icon and fonts, `Formula/` the Homebrew formula.

## Conventions this code keeps

- `BytemeterCore` has no AppKit and nothing macOS-only, and `BytemeterDashboard` uses Foundation and the engine alone, so the self-test can check the page and another platform could use both untouched.
- The self-test is a plain executable, not an XCTest target, because XCTest is not in the Command Line Tools. A new check is a function in its subject's file, called from `main.swift`, written with the helpers in `Harness.swift`.
- `VERSION` is the only place the version and the build number live. A fix moves the last number, a feature the middle one, and `BUILD` goes up by one every time; the commit message is the version.
- `Sources/BytemeterDashboard/DashboardFonts.swift` is generated by `Scripts/make_fonts.py` from `Resources/Fonts` and committed; it is never edited by hand.
- The dashboard page fetches nothing: no `<script>` and no web address, and CI fails the build if either appears.
- Swift 5.9 and macOS 13 are the floor (`Package.swift`); nothing newer is required. Building needs macOS 13.5, the first that runs Swift 5.9, which is why README and MAINTENANCE say 13.5.

## Gotchas

- `ld: warning: search path ... not found` lines under the Command Line Tools are harmless: they name folders that only full Xcode has.
- Ad hoc signed, not notarised, so there is no prebuilt download; Homebrew and a clone both build on the Mac they run on.
- A published tag never moves: the formula pins the checksum of its tarball.
- A copy of the app opened by hand is not launchd's and is not restarted after a crash, which is why the crash check in the release checks comes first.
- A clock set ahead and then corrected files readings at the last reading's minute until real time catches up. Known limit, not a bug; the 32 bit fallback's 200 MB wrap limit is another.
- No database files in the repository: `Scripts/make_demo_db.py` writes into a folder you name and refuses the app's own data folder, and `.gitignore` refuses `*.db` and its companions.

## Working here

- One task per session, with the check that proves it named at the start. Plan first only when the change touches several files; a session that has gone wrong is rewound or abandoned, not argued with.
- The test command above is the gate. It runs before anything is called done, and its output is the evidence: a report names the command that passed and the count. A failing run is reported with its output, never worked around, and a check is never weakened to make it pass.
- The task's scope is the task. No refactors, features, renames or tidying beyond what was asked; a bug found nearby is reported as a follow-up, not fixed in the same change.
- Parallel work runs one task per worktree (`claude -w <name>`; `.claude/worktrees/` is ignored by git). Each agent is given the list of files it owns and touches nothing outside it. Two agents never share a file.
- Before a commit: the diff is reviewed in a fresh context (`/code-review`, or `/simplify` for cleanups), then the gate runs again.
- Commits carry the repository's own git identity and say what changed and why. No AI attribution lines or trailers, ever.
- Nothing is pushed, tagged or released without the maintainer's yes, given in chat for that push. Force-pushes and a bare `git push` are denied in `.claude/settings.json`; a push names its remote and branch, `git push origin main`.
